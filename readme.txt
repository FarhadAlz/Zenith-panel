این پروژه دقیقاً همون چیزیه که قبلاً درباره‌ش صحبت کرده بودیم: یک پنل لوکال برای اجرای remote همون Agent قبلی (تشخیص/رفع خطاهای 500) روی سرورهای DirectAdmin، بدون نیاز به نصب دائمی چیزی روی سرور. ساختار کلی:

```
zenith-panel/
├── backend/
│   ├── main.py              → FastAPI: API + WebSocket
│   ├── ssh_manager.py       → اتصال SSH / SFTP، اجرای دستورات
│   ├── crypto_utils.py      → رمزنگاری مبتنی بر master password
│   ├── store.py             → SQLite (سرورها، تنظیمات)
│   └── agent_runtime/
│       ├── colors.py, domain_resolver.py, tools.py, safety.py, llm_agent.py  → منطق اصلی (بدون تغییر)
│       └── remote_runner.py → پل جدید: این فایل‌ها را روی سرور *دور* اجرا می‌کند
└── frontend/
    ├── index.html, style.css, app.js
```

### جریان فنی کار

**۱. راه‌اندازی و صندوق رمزنگاری (`crypto_utils.py` + `store.py`)**
اولین بار که پنل بالا می‌آید، یک "رمز اصلی" از کاربر می‌گیرد. این رمز خودش هیچ‌جا ذخیره نمی‌شود؛ فقط از آن (احتمالاً با PBKDF2/scrypt) یک کلید متقارن ساخته می‌شود که در حافظه‌ی پروسه می‌ماند و برای رمزگذاری/رمزگشایی پسورد سرورها و کلید API در `panel.db` استفاده می‌شود. با بستن پنل، کلید از حافظه می‌رود و باید رمز دوباره وارد شود.

**۲. افزودن سرور (`ssh_manager.py`)**
با زدن «افزودن سرور»، پنل یک اتصال SSH واقعی می‌زند (پسورد یا کلید خصوصی)، و اگر موفق بود، از طریق **SFTP** پنج فایل agent_runtime را در مسیر `~/.zenith_runtime/` روی همان سرور کپی می‌کند. این یعنی هیچ سرویس دائمی نصب نمی‌شود — فقط چند فایل پایتون سبک.

**۳. کشف دامنه‌ها (`domain_resolver.list_domains()`)**
یک تابع جدید و فقط-خواندنی که مسیر `/home/*/domains/*` را روی سرور (استاندارد DirectAdmin) می‌خواند و لیست دامنه/ساب‌دامنه را برمی‌گرداند — بدون اینکه منطق اصلی فایل تغییر کرده باشد.

**۴. بررسی سلامت + تشخیص/رفع زنده (`main.py` WebSocket + `remote_runner.py`)**
وقتی روی دامنه کلیک می‌کنید، ابتدا یک HTTP check ساده انجام می‌شود. اگر مشکل بود، دکمه‌ی بررسی خودکار باز می‌شود: پنل یک WebSocket باز می‌کند، از طریق SSH دستور اجرای `remote_runner.py` را روی سرور می‌فرستد (کلید API هم به‌صورت پیام کنترلی، نه env/آرگومان، تا در `ps aux` دیده نشود)، و آن فایل روی *خود سرور هدف* همان `llm_agent.py` / `tools.py` / `safety.py` قدیمی را اجرا می‌کند. خروجی هر مرحله (GREEN/YELLOW/RED) به‌صورت stream از طریق همان SSH channel به پنل و از آنجا به مرورگر شما می‌رسد.

**۵. لایه‌ی امنیتی/تأیید (`safety.py`، بدون تغییر)**
عملیات‌های ریسک‌دار (RED) اصلاً اجرا نمی‌شوند؛ عملیات‌های نیمه‌ریسک (YELLOW مثل ری‌استارت سرویس) اجرا متوقف می‌شود و پنل روی WebSocket یک درخواست تأیید می‌فرستد؛ تا کاربر «تأیید» نزند چیزی روی سرور اجرا نمی‌شود. مهم‌ترین نکته‌ی امنیتی معماری: **مدل هوش‌مصنوعی هیچ‌وقت IP/پسورد/کلید سرور را نمی‌بیند** — فقط نام ابزار + نتیجه‌ی JSON آن (مثلاً خروجی `check_service("nginx")`) به مدل داده می‌شود؛ ارتباط SSH کاملاً در لایه‌ی پایتون پنل انجام می‌شود.
