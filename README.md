# Zenith Panel

پنل لوکال، تک‌فایل‌نصب، برای مدیریت چند سرور و اجرای همان منطق تشخیص/رفع خودکار خطاهای
500/502/503 که قبلاً به‌صورت CLI (`main.py`) روی خود سرور اجرا می‌شد — با این تفاوت که
حالا **agent-less** است: روی هیچ سروری چیزی به‌صورت دائمی نصب نمی‌شود، پنل از طریق SSH
وصل می‌شود، نسخه‌ی سبک و یکبارمصرف کد ایجنت را می‌فرستد، اجرا می‌کند، و نتیجه را زنده روی
همین داشبورد نشان می‌دهد.

## معماری، خیلی خلاصه

```
مرورگر شما  <-- HTTP/WebSocket -->  پنل (FastAPI, روی کامپیوتر خودتان)  <-- SSH -->  سرور(های) هدف
```

- **پنل** تنها جایی است که IP / یوزرنیم / پسورد یا کلید سرورها و کلید API مدل هوش مصنوعی
  رمزگذاری‌شده نگه‌داری می‌شود (`backend/data/panel.db` + `backend/data/vault_config.json`).
- خود **مدل هوش مصنوعی** (LLM) هیچ‌وقت این اطلاعات را نمی‌بیند. چیزی که به مدل داده می‌شود
  فقط اسم ابزارها و نتیجه‌ی JSON آن‌هاست (مثلاً نتیجه‌ی `check_service("nginx")`)، نه IP یا
  پسورد سرور. این جداسازی در کد قبلی پروژه (`tools.py` / `safety.py` / `llm_agent.py`)
  از قبل وجود داشت و هیچ تغییری در همان منطق داده نشده — فقط یک لایه‌ی جدید (`remote_runner.py`)
  همان کد را روی سرور دور، به‌جای روی خود سرور، اجرا می‌کند.
- فایل‌های `colors.py` / `domain_resolver.py` / `tools.py` / `safety.py` / `llm_agent.py` در
  مسیر `backend/agent_runtime/` دقیقاً همان فایل‌های پروژه‌ی قبلی شما هستند (بدون تغییر منطق؛
  فقط یک تابع جدید و تماماً read-only به اسم `list_domains()` به `domain_resolver.py` اضافه
  شده تا پنل بتواند فهرست دامنه‌های هر سرور را نشان دهد). طبقه‌بندی GREEN/YELLOW/RED، تأیید
  عملیات، و منطق تشخیص/رفع همه دقیقاً همان چیزی است که قبلاً تست کرده بودید.
- هنگام اتصال به هر سرور، پنل این پنج فایل را از طریق SFTP در پوشه‌ی
  `~/.zenith_runtime/` (داخل هوم همان یوزر SSH) کپی می‌کند — چند کیلوبایت، بدون هیچ
  نصب یا سرویس دائمی. هر بار که دوباره وصل می‌شوید، این پوشه بازنویسی می‌شود تا همیشه
  آخرین نسخه‌ی منطق اجرا شود. هر وقت خواستید، می‌توانید این پوشه را از روی سرور حذف کنید؛
  دفعه‌ی بعد که پنل وصل شود دوباره می‌سازدش.

## پیش‌نیازها

**روی کامپیوتری که پنل را اجرا می‌کنید (ویندوز/مک/لینوکس):**
- Python نسخه‌ی 3.10 یا بالاتر
- دسترسی به اینترنت برای نصب پکیج‌ها (یک‌بار) و فونت Vazirmatn در مرورگر

**روی هر سروری که به پنل اضافه می‌کنید:**
- دسترسی SSH (پسورد یا کلید خصوصی)
- `python3` نصب‌شده (روی تقریباً همه‌ی سرورهای DirectAdmin/CentOS/AlmaLinux از قبل هست)
- برای اینکه «رفع خودکار» (ری‌استارت سرویس و غیره) واقعاً کار کند، یوزر SSH باید اجازه‌ی
  اجرای `systemctl restart/reload nginx|httpd|php-fpmXX` را داشته باشد (روت، یا یوزری با
  sudo بدون پسورد روی همین دستورها)

## نصب

```bash
cd zenith-panel
python3 -m venv .venv
source .venv/bin/activate        # ویندوز: .venv\Scripts\activate
pip install -r requirements.txt
```

## اجرا

```bash
cd zenith-panel/backend
uvicorn main:app --host 127.0.0.1 --port 8787
```

سپس مرورگر را باز کنید روی: **http://127.0.0.1:8787**

> پنل کاملاً لوکال است — روی `127.0.0.1` گوش می‌دهد، یعنی از بیرون همین کامپیوتر در
> دسترس نیست، مگر خودتان `--host` را عوض کنید (که برای استفاده‌ی تک‌نفره توصیه نمی‌شود).

## راه‌اندازی اولیه (فقط بار اول)

1. اولین بار که پنل را باز می‌کنید، از شما یک **رمز اصلی** می‌خواهد. این رمز:
   - هیچ‌جا ذخیره نمی‌شود (نه در دیتابیس، نه در فایل).
   - فقط برای ساختن کلید رمزگذاری اطلاعات حساس (پسورد/کلید سرورها + کلید API) استفاده
     می‌شود، آن هم موقتاً و فقط در حافظه‌ی همان پردازه‌ی در حال اجرا.
   - هر بار که پنل را می‌بندید و دوباره بالا می‌آورید، باید همین رمز را دوباره وارد کنید
     (دکمه‌ی 🔒 بالای صفحه هم پنل را فوراً قفل می‌کند).
   - **این رمز را جای امنی یادداشت کنید** — اگر فراموشش کنید، راه بازیابی وجود ندارد و باید
     فایل `backend/data/vault_config.json` و `backend/data/panel.db` را حذف کنید و از صفر
     سرورها را دوباره اضافه کنید.

2. از آیکن ⚙️ (تنظیمات) کلید API مدل را وارد کنید — همان کلید GapGPT/OpenAI-compatible که
   قبلاً با متغیر محیطی `OPENAI_API_KEY` استفاده می‌کردید. این کلید هم رمزگذاری‌شده ذخیره
   می‌شود و فقط لحظه‌ی اجرای یک بررسی، از طریق کانال SSH و به‌صورت پیام کنترلی (نه env و نه
   آرگومان خط فرمان — پس در `ps aux` روی سرور هم دیده نمی‌شود) به `remote_runner.py` روی
   همان سرور هدف داده می‌شود.

## افزودن سرور

1. دکمه‌ی «+ افزودن سرور» در نوار کناری راست.
2. نام نمایشی، IP یا هاست، پورت SSH (پیش‌فرض 22)، یوزرنیم.
3. یکی از دو روش احراز هویت را انتخاب کنید:
   - **رمز عبور** — پسورد SSH را می‌نویسید.
   - **کلید خصوصی** — کل متن کلید (مثلاً محتوای `id_ed25519` یا `id_rsa`) را پیست می‌کنید،
     و اگر روی کلید پسفریز گذاشته‌اید آن را هم وارد کنید.
4. «تست اتصال و ذخیره» — پنل واقعاً وصل می‌شود؛ اگر موفق بود:
   - سرور در تاریخچه (دیتابیس لوکال) ذخیره می‌شود،
   - کد ایجنت روی سرور آپلود می‌شود،
   - فهرست همه‌ی دامنه‌ها/ساب‌دامنه‌های آن سرور خوانده و کش می‌شود.
5. دفعه‌های بعد، همان سرور در نوار کناری هست — با یک کلیک روی «اتصال مجدد» دوباره وصل
   می‌شوید، بدون نیاز به وارد کردن دوباره‌ی اطلاعات.

## استفاده‌ی روزمره

1. روی یک سرور در نوار کناری کلیک کنید — شبکه‌ای از کارت‌های دامنه/ساب‌دامنه باز می‌شود.
2. روی هر دامنه کلیک کنید — پنل بلافاصله وضعیت HTTP آن را چک می‌کند (کد وضعیت، زمان پاسخ).
3. اگر دامنه سالم بود، همین را می‌بینید. اگر مشکل داشت (500/502/503 یا خطای اتصال)، دکمه‌ی
   «🩺 شروع بررسی و رفع خودکار» ظاهر می‌شود.
4. با زدن آن دکمه، پنل یک نشست زنده باز می‌کند: همان مراحل تشخیصی که قبلاً در ترمینال
   می‌دیدید (چک سرویس‌ها، لاگ‌ها، دیسک، پرمیشن‌ها و…) این‌بار به‌صورت یک لاگ زنده و
   رنگی (GREEN/YELLOW/RED) در همین پنجره نمایش داده می‌شود.
5. هر وقت ایجنت به یک عملیات **YELLOW** (مثل ری‌استارت سرویس) برسد، اجرا متوقف می‌شود و
   یک کادر تأیید نشان داده می‌شود — دقیقاً مثل قبل که در ترمینال `y/N` می‌پرسید، فقط این‌بار
   با دو دکمه‌ی «تأیید و اجرا» / «رد کردن». عملیات **RED** هیچ‌وقت اجرا نمی‌شود.
6. در پایان، گزارش نهایی (Root Cause، اقدامات انجام‌شده، وضعیت تأییدشده) به‌صورت بخش‌بخش
   نمایش داده می‌شود، و وضعیت دامنه دوباره خودکار چک می‌شود.

## نکات امنیتی

- کلید رمزگذاری هرگز روی دیسک نیست؛ فقط از رمز اصلی شما، در لحظه‌ی باز کردن پنل، ساخته
  می‌شود و در حافظه می‌ماند.
- مدل هوش مصنوعی هیچ دسترسی مستقیمی به SSH ندارد و هیچ‌وقت پسورد/کلید/IP سرور را در پرامپت
  یا در نتیجه‌ی هیچ ابزاری نمی‌بیند — فقط پنل (کد پایتون، بدون مدل) با سرور صحبت می‌کند.
- هر عملیات تغییردهنده (ری‌استارت سرویس، پاک‌سازی لاگ) قبل از اجرا نیاز به کلیک تأیید
  دستی شما دارد؛ این تصمیم هیچ‌وقت خودکار گرفته نمی‌شود مگر عمداً آن را عوض کنید.
- توصیه می‌شود این پنل را فقط روی کامپیوتر شخصی/کاری خودتان اجرا کنید، نه روی سروری که
  از بیرون در دسترس است.

## عیب‌یابی سریع

| مشکل | راه‌حل |
|---|---|
| «احراز هویت ناموفق بود» هنگام افزودن سرور | یوزرنیم/پسورد/کلید را دوباره چک کنید؛ برخی سرورها ورود مستقیم روت با پسورد را می‌بندند — از یوزر دیگر یا کلید استفاده کنید. |
| فهرست دامنه خالی است | یعنی ساختار `/home/*/domains/*` روی آن سرور DirectAdmin نیست، یا یوزر SSH به آن مسیر دسترسی خواندن ندارد. |
| «پاسخی از سرور دریافت نشد» | مطمئن شوید `python3` روی سرور در PATH است (`which python3` را از طریق یک ترمینال SSH دستی چک کنید). |
| عملیات YELLOW با «operator_denied»/شکست مواجه می‌شود | یوزر SSH اجازه‌ی `systemctl restart/reload` روی آن سرویس را ندارد — با `sudo -n systemctl restart nginx` تست کنید. |
| گزارش نهایی خالی/عجیب است | کلید API را در تنظیمات دوباره بررسی کنید (باید کلید معتبر GapGPT/OpenAI-compatible باشد). |
